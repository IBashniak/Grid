# Правила взаимодействия и разработки для проекта

## 1. Строгое разделение вопросов и команд к действию

- **Если пользователь задает вопрос** (например: *«все ли установлено?»*, *«как устроен этот модуль?»*, *«какой сейчас статус?»*, *«где находится файл?»*):
  - Агент обязан **только ответить на вопрос**: предоставить факты, объяснить информацию, показать текущее состояние.
  - **ЗАПРЕЩЕНО:** самовольно выполнять действия, устанавливать пакеты, модифицировать файлы, запускать непредусмотренные скрипты, создавать коммиты или делать что-либо сверх прямого ответа на вопрос.
- **Если пользователь дает явную команду к действию** (например: *«установи...»*, *«сгенерируй код...»*, *«исправь ошибку...»*):
  - Агент выполняет строго запрошенную задачу, не выполняя несогласованных побочных действий.

---

## 2. Контроль коммитов в Git

- **ЗАПРЕЩЕНО создавать коммиты без предварительного подтверждения пользователя.**
- Перед созданием коммита агент обязан:
  1. Показать список измененных и добавляемых файлов (`git status`).
  2. Предложить сообщение коммита.
  3. Спросить у пользователя: *«Нужно ли создать коммит со следующим составом и сообщением?»*
  4. Создавать коммит только после явного согласия пользователя.

---

## 3. Изоляция и защита этапов проекта

- Каждый этап сквозного семестрового проекта реализуется в собственной изолированной директории. Для совместимости с правилами именования Python-пакетов (PEP 8) в именах директорий используется нижнее подчеркивание (`snake_case`: `source/grid_ray/`, `source/grid_docker/`, `source/grid_k8s/`, `source/grid_chaos_finops/`; директория Этапа 1 `source/grid_mimd/` сохраняется без изменений для обратной совместимости).
- Код, документация и тесты предыдущих этапов никогда не модифицируются и сохраняют 100% обратную совместимость.
- Тесты для новых этапов добавляются в отдельные файлы в каталоге `tests/`.
